# Normalize All Format Issue Log

This is the shared prevention log for `normalize-all`. Read it before editing an active problem. Add only recurring formatting or validation gotchas, not mathematical solution gaps.

| ID | Observed pattern | Prevention rule | First noted |
|---|---|---|---|
| F001 | Prose paragraphs were split into many fixed-width source lines. | Keep each prose paragraph on one natural source line. Insert line breaks only at semantic paragraph boundaries or required Markdown, LaTeX, step, and list boundaries. | problem 110 |
| F002 | Problem text used `\(...\)` and `\[...\]` delimiters. | Convert all inline math to `$...$` and all display math to `$$...$$` during Phase 1. | problem 130 |
| F003 | Formatted solutions retained `\tag{...}` equation labels and later referenced them. | Remove equation tags and restate the needed identity locally in prose or an unlabeled display. | problem 130 |
| F004 | The boxed answer was not the last line of the final step. | Put all final normalization and factor-coprimality prose before the final answer line; end the final step with exactly `Final Answer: $\boxed{...}$`. | problem 130 |
| F005 | Extra sections such as verification or confidence appeared in the portal solution, and required sections were out of order. | Keep the portal structure in this order: `## Steps`, `## Answer`, `## Classification`, `## Solution Concepts`, then `## Black-Box Audit`. Remove non-required auxiliary sections from the normalized solution. | problems 110 and 130 |
| F006 | `## Solution Concepts` was written as a semicolon-separated sentence instead of a list. | Use one to five adjacent Markdown bullet items, each a short plain-text concept with no LaTeX. | problem 130 |
| F007 | References to numbered equations / `\tag` labels remained after equation tags were removed. | Replace a numbered-equation reference with a local restatement of the identity, or with an explicit `Step N` pointer. Step references themselves are allowed when they name the step (`from Step 2`); only vague/positional pointers need rewriting. | problem 130 |
| F008 | A request to reduce blank lines was misread as permission to flatten display math and change its layout. | Reduce only decorative empty lines outside math. Never reduce indentation, compact `$$...$$`, move delimiters, or alter any nonempty line inside a math block. | problem 130 |
| F009 | An aligned equation used `{}` as a spacer before `&`, producing a Set Braces validator error. | In aligned environments, write `D &= ...` and never use `{}` as an alignment spacer. Reserve `\{...\}` for visible set braces and use `\{\}` for an intentional empty visible set. | problem 130 |
| F010 | A multi-character exponent was left unbraced when followed immediately by another symbol, such as `t^nh` or `u^jS`. | Group the exponent itself, preserving the intended multiplication: write `t^{n}h` and `u^{j}S`, not `t^{nh}` or `u^{jS}`. | problem 54 |
| F011 | A single-character exponent was followed immediately by an identifier, such as `(-1)^je_j`, so the validator parsed the identifier as part of the exponent. | Brace the single-character exponent, such as `(-1)^{j}e_j`, and write factorial equalities as `$3! = 6$`, not `$3!=6$`. | problem 88 |
| F011 | A named mathematical method was written with a double hyphen, such as `Cauchy--Binet`, in prose or a concept label. | Use a single hyphen in the compound name or write the name as ordinary words; reserve double hyphens for no prose output. | problem 139 |
| F012 | A prose rewrite left an inline math delimiter unclosed, such as `modulo $3, so`, causing the parser to treat the remainder of the solution as math mode. | Close every inline math span before punctuation or prose, such as `modulo $3$, so`, and run a full delimiter-balance scan after rewriting. | problem 155 |
| F013 | The portal Set Braces checker misread the temporary notation `\mathscr{S}` as an unescaped set-brace expression. | Use plain `S(L)` for the symmetric-square map notation when the portal parser flags `\mathscr{...}`. | problem 137 |
| F014 | The final subgroup expression used coordinate symbols and a semidirect-product action that were not explicitly introduced in the prompt. | Define every nonstandard answer symbol and the group action in the prompt before the final-answer constraints. | problem 119 |
| F015 | The portal Set Braces checker misread labels such as `\xrightarrow{q}` and `\xrightarrow{p}` as visible set braces. | When the map names are already defined in prose, use an unlabeled `\longrightarrow` chain to avoid parser ambiguity. | problem 119 |
| F016 | The portal Set Braces checker flagged path notation written with `\mathbin{-}` inside a display block. | Write simple path notation such as `0-z-a` instead of `\mathbin{-}` when no special spacing is needed. | problem 150 |

| F016 | The solution Answer field used display math with `\boxed{...}` instead of the required inline unboxed expression. | Keep the final-step box and Answer field identical in content, but write the Answer field as one inline `$...` expression without `\boxed`. | problem 154 |
| F017 | Domain Explanation prose contained formulas or omitted the required three-sentence scaffold. | Write exactly three plain-English sentences in the required key-elements, additional-elements, and non-core-role order, with no LaTeX, math symbols, or colons. | problem 149 |
| F018 | The portal Set Braces checker misread affine-group notation such as `7{:}6` as visible set braces. | Write affine-group notation as `7:6` and avoid braces around the colon. | problem 149 |
| F019 | The LaTeX parser treated indicator shorthand such as `\mathbf1` and an unbraced product exponent such as `^mF` as malformed syntax. | Write indicators as `\mathbf{1}` and brace every exponent before an adjacent symbol, such as `\prod_{i=1}^{m}F(z_i)`. | problem 158 |
| F020 | The portal inline parser still rejected a boxed answer containing a nested indicator with multiple subscript braces. | Define a simple prompt-level auxiliary quantity such as `\epsilon_i` and use it in the boxed and Answer expressions. | problem 158 |
| F021 | An inline math span such as `$6` without a closing delimiter made the parser report an unclosed `$` at the final answer instead of at the source sentence. | Run a delimiter-state scan after every prose edit and close each inline span before continuing the sentence. | problem 158 |
| F022 | The portal Set Braces checker misread a spacing command such as `\hspace{35mm}` as an unescaped visible-brace expression. | Remove decorative `\hspace{...}` padding from aligned math, or replace it with parser-safe alignment that does not contain a spacing argument. | problem 161 |
| F022 | Fractions such as `\frac12` and `\frac1n` remained in normalized math and could be parsed inconsistently. | Write every fraction with braced numerator and denominator, such as `\frac{1}{2}` and `\frac{1}{n}`. | problem 162 |
| F023 | A LaTeX row separator followed immediately by a parenthesis, such as `\\(i,j)`, was parsed as the forbidden inline delimiter `\(`. | Add a space after the row separator, such as `\\ (i,j)`, and scan the full file for accidental `\(` or `\[` delimiters. | problem 53 |
| F024 | A single-character subscript followed immediately by an identifier, such as `F_kh_1` or `X_dX`, was merged by the portal parser. | Brace the subscript before the adjacent identifier, such as `F_{k}h_1` and `X_{d}X`. | problem 145 |
| F025 | Adjacent variables such as `nu^4` were parsed as the command `\\nu` by the missing-backslash checker. | Insert explicit multiplication spacing between adjacent single-letter factors, such as `n\\,u^4`, instead of writing `nu^4`. | problem 163 |
| F026 | The portal Set Braces checker misread `\\mathscr{C}_n` as an unescaped set-brace expression. | Use the plain symbol `C_n` for the prompt-defined polynomial family when the parser flags `\\mathscr{...}`. | problem 165 |
| F027 | Bracing every `\\mathbb{Z}` argument expanded an exhaustive set answer past the 100-character Answer Length Gate. | When the parser accepts it and the notation is already prompt-defined, use the compact standard form `\\mathbb Z` consistently in the answer; otherwise redesign the answer type rather than abbreviating the object. | problem 167 |
| F028 | The Set Braces checker misread modulo notation written as `t\\mathbin{\\{\\bmod\\}}N` as a visible-brace expression. | Write modulo notation as `t\\mathbin{\\bmod}N` without visible braces around the operator. | problem 170 |
| F029 | Replacing display delimiters before handling a `cases` row separator such as `\\[2mm]` produced malformed text like `\$$2mm]`. | Normalize `cases` row spacing before converting `\[` delimiters, or explicitly restore every non-final row to `\\` and scan for malformed `\$$...` sequences. | problem 137 |

| F030 | A piecewise `cases` expression in the final answer field violated the portal's no-cases rule. | Define a prompt-level indicator and express the final answer as a case-free product of indicators. | problem 172 |
| F031 | The portal Set Braces checker misread `\mathrel{\Big|}` inside a conditional-expectation expression as a visible-brace construct. | Write the conditional bar as `\,\Big|\,` without wrapping it in a command argument. | problem 150 |
| F032 | A problem statement or solution verification included portal-side instructions such as counting answer characters after removing whitespace. | Keep answer and solution length checks in workflow gates only; never place validator instructions, character counts, or submission-field directions in `problem.md` or `solution.md`. | problem 165 |
| F033 | Standardizing every nested fraction and delimiter in a compact symbolic answer pushed the final Answer over the 100-character gate. | When the expression is mathematically identical and no notation is hidden, use a parser-safe equivalent such as a negative exponent in the final answer, then verify the exact character count. | problem 155 |
| F034 | A normalization edit emitted commands such as `\mathbb`, `\ldots`, and `\geq` without their backslashes in the problem text. | After every patch, scan both output files for bare command names and verify every LaTeX command retains its backslash before running portal checks. | problem 155 |

| F035 | The portal parser treated optional row spacing such as `\\[2pt]` after a matrix row separator as a forbidden `\\[` delimiter. | Remove decorative optional row spacing from aligned math and use a plain `\\` row separator. | problem 85 |
| F036 | The portal Set Braces checker flagged the grouping braces in `\\mathbin{\\bmod}` even though they are command syntax. | Write the standard modulo operator directly as `\\bmod`, for example `t\\bmod N`, and do not add visible braces around the operator. | problem 170 |

| F037 | A file patch passed through an escaped command string lost backslashes from LaTeX commands. | Use a raw patch literal for LaTeX content, then scan both output files for missing backslashes and malformed delimiters. | problem 179 |
| F038 | Text labels in subscripts used the legacy command \rm, which is less reliable in the portal parser. | Use \mathrm{...} for textual labels inside math, such as \sum_{r\ \mathrm{odd}}. | problem 167 |
| F039 | The portal Set Braces checker misread \mathbin{\cdot} as a command argument containing braces. | Use the plain multiplication operator \cdot when no special spacing is needed. | problem 167 |
| F040 | The In-Inequality checker treated `\sum_{v\in L}` inside a colon-delimited set builder as an ambiguous inequality-membership combination. | In that set builder, write the summation condition as `\sum_{v\text{ on }L}` or equivalent prose so no `\in` occurs in the flagged context. | problem 142 |
| F041 | The In-Inequality checker rejected an indexed array followed immediately by membership notation, such as `(c_{ij})_{1\leq i<j\leq n}\in R^N`. | State in prose that the array has entries in the ring, and keep the displayed indexed array free of `\in`. | problem 162 |
| F042 | An earlier solution step announced that its result was "needed in Step 4," creating a forward reference. | Permit numbered references only to earlier steps. State an earlier step's conclusion locally without naming any later step or announcing future use. | problem 171 |
| F043 | The portal Set Braces checker misread the grouping braces in `\mathbin{\oplus}` as visible set braces. | Use the standard binary operator `\oplus` directly because it already has the correct spacing. | problem 154 |

## Entry format
For a new recurring issue, append a row with the next ID, the observed pattern, the concrete prevention rule, and the first problem where it appeared. Keep entries short and actionable.
