# Rainier Submit — Submission Packager and Pre-Submission Gate

## Contract

- **Task:** assemble one normalized `problemNN-*/` folder into the Rainier portal submission fields, run every hard-constraint gate and the Final Checklist, and present a copy-paste-ready package in chat. Does **not** author or rewrite content and does **not** create files — it only maps and validates the already-authored `problem.md`/`solution.md`.
- **Defaults (act, do not ask):** proceed on the most reasonable reading. Resolve the target folder from context per `skills/_shared/frontier_workspace.md`; if no folder is unambiguous, use the most-recently-modified `workspace/frontier-problem/problemNN-*/` and state that assumption in the report. Map fields and run all gates autonomously; on a gate FAIL, report the specific gap and hand back to the named fix skill rather than presenting the package as ready.
- **Only hard stop:** a required file (`problem.md` or `solution.md`) is missing, empty, or clearly not yet normalized — then say to run `/normalize-all` and stop. Nothing else pauses the run.
- **Done:** the mapped package is printed to chat with every hard-constraint gate and the Final Checklist reported, and no file was created. Persist end-to-end in this turn; do not narrate a plan before acting.

## Global Principle

**Rainier forbids LLM-generated submission content.** Everything in `problem.md` and `solution.md` must be human-authored. This skill is a packaging and verification step only — treat its output as a checklist and a field map, not as generated content to paste verbatim without human ownership.

**Edit-scope discipline (read `skills/_shared/edit_scope_discipline.md`).** This skill does not author or rewrite content, so it never edits the `Domain Explanation` or the steps on its own. Its role here is to **verify, before submit, that the two things reviewers most often send back are already clean**: (1) no reviewer-fillable justification gap remains — every step whose justification a reviewer could reasonably request in one or two sentences already contains it (Black-Box Level 2 / Compressed-Rigor, `skills/_shared/hard_gates.md`); and (2) the `Domain Explanation` is genuinely good, not merely scaffold-compliant. If either fails, do not silently fix it — report it and hand back to `format-solution`/`math-harder` for a scoped repair.

## Step 0 — Resolve the active problem

Read `skills/_shared/frontier_workspace.md`.

- If a folder path was passed to this skill, use that `workspace/frontier-problem/problemNN-*` folder.
- Otherwise apply the folder-resolution default from the Contract above (context folder, else the most-recently-modified `problemNN-*`).
- Read that folder's `problem.md` and `solution.md`.
- If either file is missing, empty, or clearly not yet normalized, stop and tell the user to run `/normalize-all` first.

## Step 1 — Preconditions

Confirm the problem has been normalized and solved:

- `problem.md` has `## LaTeX (Normalized)`, a `## Domain Classification` table (Domain, Sub-domain, Problem Type, Answer Type), and `## Domain Explanation`.
- `solution.md` has `## Steps` (each step `Step N:`, final step ends `Final Answer: $\boxed{...}$`), `## Answer`, `## Classification`, and `## Solution Concepts`.

If anything is missing, stop and point the user to `/normalize-all` (which also runs this skill as its final phase).

## Step 2 — Difficulty reminder (portal-side)

The portal tests the problem against **two frontier "hard" models**, and **both must consistently get the wrong answer** (official bar: stumps at least one frontier model the majority of the time). Remind the user to run this in the portal **before** submitting, and that `"No response was generated by the model"` is not the same as a wrong answer — re-run if it appears.

## Step 3 — Map folder content to portal fields

Present each portal field with the exact content drawn from the folder. Do not paraphrase the math.

| Portal field | Source |
|---|---|
| **Math Problem (Prompt)** | `problem.md` → `## LaTeX (Normalized)` (verbatim) |
| **Domain** + **Sub-domain** | `problem.md` → `## Domain Classification` (must be one of the 13 domains in `skills/_shared/taxonomy_slots.md`) |
| **Domain Explanation** | `problem.md` → `## Domain Explanation` (the 3-part scaffold: "This problem involves … which are part of <domain/sub>. The problem also involves … which are part of <other>. However, <why not core>.") |
| **Worked Solution** | `solution.md` → `## Steps` (each `Step N:`; final line `Final Answer: $\boxed{...}$`; references to earlier steps written as "Step 2") |
| **Answer** | `solution.md` → `## Answer`, wrapped in `$...$`, **with `\boxed` removed** (the Answer field must not use `\boxed`) |
| **Problem Type** | `## Classification` Problem Type (exactly one) |
| **Answer Type** | `## Classification` Answer Type (exactly one) |
| **Concepts** | `solution.md` → `## Solution Concepts` (map verbatim — `format-solution` derives these from the solution). **Backstop only**: if that section is missing, derive **1–5** concepts/techniques/knowledge from `solution.md` (e.g. for a calculus problem: critical points, first-derivative sign changes, endpoint comparison) and note that they were derived here rather than during normalization. |

## Step 4 — Rainier hard-constraint gate (automatic-reject checks)

Each is an explicit disqualifier. Report PASS/FAIL with the specific reason for any FAIL. Read `skills/_shared/hard_gates.md` and check every rule there: the By-Hand Solution Gate, the hand-solvable magnitude bounds, the no-DNE rule, the no-obscure-topic rule, the Answer Length Gate, and the Solution Length Gate. If the By-Hand Solution Gate FAILs or is skipped, the package is not acceptable for Rainier review.

- **Answer Length Gate (HARD GATE, in-app-enforced)**: strip every `$` and every whitespace character from the `## Answer` field and count what remains. Report the exact count. FAIL if it is 100 or more — the in-app Evaluation Check LaTeX button will reject it on submission regardless of this report. This gate is unconditional here: `hard_gates.md` grandfathers only already-finalized problems sitting untouched in the portal, and assembling a submission through this skill is not that case, so no prior ACCEPTED/DELIVERED/READY_TO_DELIVER status exempts the answer.

- **Solution Length Gate (HARD GATE)**: count every character of the `## Steps` section of `solution.md` — as written, including LaTeX and whitespace; nothing outside the section counts. Report the exact count. FAIL if it is 10,000 or more (`skills/_shared/hard_gates.md`, effective 2026-07-19). Fixing a FAIL means honest compression (tighter prose, certificate-style arguments), never re-hiding steps behind black boxes.

- **Contrived-terminology / stacked-definition (Probe P2/P8, report-only)**: read `skills/_shared/triviality_probe.md` and check the `## LaTeX (Normalized)` prompt against **P2** (decoration — any defined term/component whose deletion leaves the answer unchanged) and **P8** (terminology-density — FAIL if the prompt introduces four or more bespoke defined terms/labels, forces the reader to hold more than three definitions at once, or renames a concept that already has a standard taxonomy name; ≤2 preferred below the cap). This is the portal's "Beyond Project Scope" reject reason and the submission-side last line of defense for problems authored before P8 existed. This skill does not edit content, so on FAIL do not condense here — stop and tell the user to fix it via `/math-harder` (whose P2/P8 pre-pass does the answer-preserving condense). P2 and P8 are non-waivable.
- **No proofs**: the prompt does not ask to "show that", "prove", or "verify".
- **Not guessable / no word puzzle**: not yes/no, not multiple choice, not a word puzzle.
- **Self-contained answer notation**: the answer uses only notation introduced in the prompt.
- **Single question**: exactly one question, no sub-parts.
- **LaTeX**: only `$...$` and `$$...$$` (no `\(...\)`, no `\[...\]`); the `## Answer` field has no `\boxed`; the final solution step ends with `Final Answer: $\boxed{...}$` whose content matches the Answer field.
- **LaTeX "Other Style"**: enforce the Plain Portal Text Gate from `skills/_shared/hard_gates.md`; no Markdown emphasis or blockquotes in the Problem or Steps, no empty lines between consecutive list items, no `\item[]`, and no KaTeX-only commands (use standard LaTeX, e.g. `\langle`/`\rangle`, never `\lang`/`\rang`).

If any gate FAILs, stop and tell the user to fix it (via `/math-harder`, `/math-change-answer-type`, or by editing the source) before submitting. Do not present the package as ready.

## Step 4b — Acceptance freeze reminder

On acceptance, apply the Acceptance-freeze rule in `skills/_shared/frontier_workspace.md` (`### Acceptance freeze`): freeze evaluation and never inherit an earlier version's stump/solve numbers.

## Step 5 — Final Checklist (portal)

Confirm and report each:

- There is **one and only one** correct answer.
- Spelling and grammar checked.
- Solution steps **independently verified** (each step recomputed without trusting the final answer).
- LaTeX formatting is correct.

Output to **chat only** (do not create any file — the folder keeps exactly `problem.md` and `solution.md`):

```

## Gate results
- Hard-constraint gate: [PASS / FAIL — reasons]
- Final Checklist: [all confirmed / list gaps]
- Difficulty: [reminder — test vs 2 models on portal; both must be wrong]

## Fields to paste

<verbatim normalized LaTeX>

### Domain / Sub-domain
<domain> / <sub-domain>

### Domain Explanation
<3-part scaffold text>

### Worked Solution
<Step 1: ... ; ... ; Final Answer: $\boxed{...}$>

### Solution Concepts

- <concept 2>

Recommend "Quality Review" if all gates pass; otherwise "Automated Checks Only" to preview difficulty and originality while fixing gaps.

## Reminder
Run the mandatory In-App Evaluation in the portal before submitting.
```

## Hard Rules

- **DO NOT** author, rewrite, or invent any mathematical content — only map and validate what is already in the folder.
- **DO NOT** create or modify any file. The problem folder keeps exactly `problem.md` and `solution.md`; the package is presented in chat.
- **DO NOT** present the package as submission-ready if any Step 4 gate or Step 5 checklist item fails — report the gap and stop.
- **DO NOT** put `\boxed` in the Answer field; **DO** keep `Final Answer: $\boxed{...}$` as the last line of the final solution step, matching the Answer field.
- **DO NOT** select a Domain/Sub-domain, Problem Type, or Answer Type outside `skills/_shared/taxonomy_slots.md`; remember domain quotas are live on the portal and a wrong/full category may be rejected.
- **DO** remind the user that submission content must be human-authored and that the In-App Evaluation is mandatory.
